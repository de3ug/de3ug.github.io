VIPeR

Viewpoint Invariant Pedestrian Recognition

We created VIPeR to evaluate appearance models across changes in camera viewpoint, pose, and illumination. It contains two images of each of 632 pedestrians.

Dataset details

TaskAppearance-based person re-identification: rank gallery images for a probe captured from another camera.
Identities632, with two images per identity.
Images1,264 RGB BMP images; 48 pixels wide × 128 pixels high.
StructureVIPeR/cam_a/, VIPeR/cam_b/, and the original README.txt.
PairingMatch filenames by their numeric identity prefix, such as 001 in 001_45.bmp. Identity numbers have gaps.
ViewpointsArbitrary camera viewpoints; most pairs differ by at least 90 degrees. Filenames include coarse viewpoint labels.
CollectionWe collected footage with two cameras in an academic setting. Subjects were notified of the cameras and were not coached.
ReleaseVersion 1.0, September 22, 2007, UCSC Computer Vision Lab.
AuthorsDouglas Gray, Shane Brennan, and Hai Tao.
Archive19,756,977 bytes. Original ZIP and README preserved unchanged.

VIPeR is a small, closed-world benchmark with hand-cropped, low-resolution images and only one observation per identity per camera. It does not measure detection performance, long-term tracking, changing clothes, open-world identification, or deployment accuracy. It has no demographic annotations and should not be used to infer demographic fairness.

Evaluation protocol

Use 5x2 cross-validation to evaluate appearance matching, keeping both images of each identity in the same fold:

  1. Randomly divide the 632 identity pairs into two folds, A and B, of 316 identities each.
  2. Train on A and test on B. Then train a fresh model on B and test on A.
  3. Repeat with five randomized partitions in total. This gives five rounds, each with two train/test evaluations, or ten evaluations per method.
  4. Randomize image-pair order and image mirroring. Within each test fold, use one image per identity as gallery and the other as probe; swap gallery and probe and average both directions.
  5. Average cumulative matching characteristic (CMC) curves over the folds and rounds. Report the gallery size alongside the curves.

Train/test reversal and gallery/probe reversal are separate steps. The first changes which identities the model learns from; the second changes the matching direction within the same test identities.

For details, see Section 4.3 of our PETS paper and Section 3.5 of Dietterich (1998), which defines five repetitions of two-fold cross-validation. Five random train/test splits without reversing the folds are a different protocol.

There are no fixed train/test split files in the original release. Record random seeds and generated identity assignments when reproducing this protocol. State any different protocol explicitly, including external training data, gallery size, or re-ranking.

Use rank one to measure how often the top match is correct. Higher ranks measure whether the correct identity appears in a shortlist for a human operator. For the relationship between these curves, tracking, and reacquisition, see Section 4.2 of our PETS paper.

Loading a pair

After extracting the ZIP, pair images by identity rather than by directory order. This Python example uses Pillow:

from pathlib import Path
from PIL import Image

root = Path("VIPeR")
def by_identity(camera):
  return {
    path.stem.split("_")[0]: path
    for path in (root / camera).glob("*.bmp")
  }

a = by_identity("cam_a")
b = by_identity("cam_b")
assert a.keys() == b.keys()
identity = sorted(a)[0]
image_a = Image.open(a[identity]).convert("RGB")
image_b = Image.open(b[identity]).convert("RGB")

Treat filename viewpoint labels as coarse annotations, including the label exceptions noted above.
